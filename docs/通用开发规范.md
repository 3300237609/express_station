# 通用开发规范（可复用习惯文档）

> 适用范围：本规范是从一个实际项目中提炼的**个人开发习惯**，与具体业务解耦，可直接复制到任何新项目作为团队/个人约定。
> 文中 `<Xxx>` 均为占位符；标注「⚡默认技术栈」的章节与 Spring Boot + MyBatis 绑定，其余章节（分层、Javadoc、错误文案、注释、模板）与技术栈无关，换框架依然适用。

---

## 1. 默认技术栈 ⚡

| 类别 | 选型 |
|---|---|
| 基础框架 | Spring Boot（`jakarta.*` 命名空间，JDK 17+） |
| 构建 | Maven |
| 持久层 | MyBatis + XML Mapper（不用 JPA / MyBatis-Plus） |
| 数据库 | MySQL + Druid 连接池 |
| 分页 | PageHelper 与手动 `LIMIT` 二选一，**新项目统一 PageHelper** |
| 认证 | Spring Security + JWT + HttpOnly Cookie（无状态过滤器链） |
| 工具库 | Hutool、Lombok |
| 简化代码 | 实体/DTO/VO 一律 `@Data` |

## 2. 目录结构

```
src/main/java/<包根>/
├── XxxApplication.java           # 启动类
├── controller/                   # 控制层：参数接收 + 转发，不写业务
├── service/                      # 业务层接口
│   └── Impl/                     # 业务层实现（一个接口对应一个 Impl）
├── mapper/                       # MyBatis Mapper 接口（@Mapper）
├── entity/                       # 数据库表实体
├── dto/                          # 请求入参对象
├── vo/                           # 出参视图对象
├── config/                       # 配置类（Security/跨域/数据源）
├── common/                       # 横切基础类（统一响应 R 等）
├── security/                     # 认证授权（JwtUtils 签发校验、JwtAuthenticationFilter）
├── utils/                        # 静态工具类（SecurityUtils 当前登录人、加解密等）
├── filter/                       # Servlet 过滤器（按需新增，FilterRegistrationBean 注册）
├── tool/                         # （可选）第三方能力函数，如 Spring AI @Tool
└── constant/                     # 常量类（提示词、枚举值、固定文案）
```

```
src/main/resources/
├── application.yml               # 主配置（一个项目只保留一个配置入口文件）
├── mybatis/
│   ├── mybatis-config.xml        # 全局 settings
│   └── mapper/*.xml              # XML 与 Mapper 接口同名对应
└── static/
```

**原则**：按技术角色横向分包，业务靠**类名前缀**关联（`XxxController` / `XxxService` / `XxxMapper` / `XxxMapper.xml`）。

## 3. 分层职责与调用链

```
HTTP → Spring Security 过滤器链（JwtAuthenticationFilter 校验 Token，白名单与 OPTIONS 预检放行，认证信息写入 SecurityContextHolder）
     → Controller   只做参数接收 + 转发，Javadoc 按第 5 节规范
     → Service      参数校验 → 查库 → 组装，返回统一响应（当前登录人用 SecurityUtils.getCurrentUserId()）
     → Mapper       接口方法 + XML SQL，无逻辑
```

- Controller **不注入 Mapper**，只注入 Service；Service 用 `@Autowired` 字段注入 Mapper（不用构造器注入）。

## 4. 统一响应与分页

### 4.1 统一响应对象 `R<T>`

```java
R.success(data)             // 成功，code=1，data 放业务数据
R.success("操作成功！")      // 成功（增删改），data 放提示文案
R.error("错误信息！")        // 失败，code=0，msg 放错误文案
r.add("key", value)         // 动态扩展字段（分页信息等）
```

响应体固定结构：`{ code, msg, data, map }`。**所有接口都返回这个结构**，文件流导出接口除外（直接写 HttpServletResponse）。

### 4.2 分页模板（默认值统一 pageNum=1、pageSize=10）

```java
// Service 内
PageHelper.startPage(pageNum, pageSize);
List<XxxVO> list = xxxMapper.selectList(...);
PageInfo<XxxVO> pageInfo = new PageInfo<>(list);
return R.success(list)
        .add("total", pageInfo.getTotal())
        .add("pageNum", pageInfo.getPageNum())
        .add("pageSize", pageInfo.getPageSize())
        .add("pages", pageInfo.getPages());
```

Controller 参数声明：

```java
@RequestParam(defaultValue = "1") Integer pageNum,
@RequestParam(defaultValue = "10") Integer pageSize
```

## 5. Controller 层：四字段 Javadoc 规范 ★核心

每个接口方法上方固定写 **1 行功能描述 + 4 个字段**，字段按请求形态选用：

```java
/**
 * 功能描述（可注明使用角色，如“（教师）”）
 * 请求方式：GET|POST|PUT|DELETE
 * 请求路径：/xxx/yyy
 * 请求参数：a（说明）、b（说明，可选）     ← GET 查询参数用这行
 * 请求体：XxxDTO（字段1、字段2）          ← POST/PUT 请求体用这行
 * 路径参数：id（说明）                    ← /{id} 形态用这行，可与上面并列
 * 返回值：xxx列表|操作结果|xxx详情
 */
@GetMapping("/{id}")
public R<XxxVO> detail(@PathVariable Long id) {
    return xxxService.detail(id);
}
```

- 路径参数行、请求参数行、请求体行**至少出现一行**（无参接口可省略参数行，但方式/路径/返回值必须有）。
- 类头同样三行：`业务名控制层` / `处理xxx相关HTTP请求` / `基础路径：/xxx`。

### 5.1 URL 与 HTTP 方法习惯

| 业务 | 方法+路径 | 请求形态 |
|---|---|---|
| 查列表 | `GET /xxx/list` | 可选筛选 + 分页参数 |
| 查详情 | `GET /xxx/detail/{id}` | 路径参数 |
| 新增 | `POST /xxx/add` | `@RequestBody` |
| 修改 | `PUT /xxx/update` | `@RequestBody` |
| 删除 | `DELETE /xxx/delete/{id}` | 路径参数 |
| 条件查询（参数复杂时） | `POST /xxx/queryXxx` | 请求体传 ID/条件 |
| 文件导出 | `GET /xxx/export/{id}` | 直接写响应流，返回附件 |

- **动词进路径**（`add/update/delete/list`），不用 REST 资源名风格。
- 路径与方法名小驼峰对应：`getNameById` → `/xxx/getNameById`。

### 5.2 参数绑定习惯

```java
@RequestParam(required = false) Long clazzId,           // 可选查询参数
@RequestParam(defaultValue = "1") Integer pageNum,      // 带默认值
@RequestBody Xxx xxx,                                  // 简单请求体（直接收实体）
@Valid @RequestBody XxxDTO dto,                        // 带校验的请求体
@PathVariable Long id                                  // 路径参数
```

- 方法体**只写一行转发**：`return xxxService.yyy(...)`；文件流接口加 `throws IOException`。

## 6. Service 层写法

### 6.1 结构

- 接口 `service/XxxService.java` + 实现 `service/Impl/XxxServiceImpl.java`。
- 实现类 `@Service` + `implements XxxService`，方法一律 `@Override`。
- 接口方法写中文 Javadoc（`@param`/`@return`）；实现方法上方写「一行概括 + 一行职责」。

### 6.2 方法内部固定步骤顺序 ★核心

用编号注释 `// 1. // 2. ...` 逐行推进：

```java
@Override
public R<String> doSomething(XxxDTO dto) {
    // 1. 参数校验（空判断，文案说明缺哪些字段）
    if (!StringUtils.hasText(dto.getName())) {
        return R.error("名称不能为空！");
    }
    // 2. 数据存在性校验
    Xxx old = xxxMapper.selectById(dto.getId());
    if (old == null) {
        return R.error("数据不存在！");
    }
    // 3. 业务规则（如：有关联数据则禁止删除）
    // 4. 执行写操作，检查影响行数
    int rows = xxxMapper.update(dto);
    if (rows <= 0) {
        return R.error("修改失败！");
    }
    return R.success("修改成功！");
}
```

**硬性习惯：**

1. 顺序固定：**空校验 → 存在性 → 业务规则 → 执行**；错误提前 `return R.error(...)`，**不抛异常**。
2. 错误文案：**中文 + 全角感叹号 `！`**，尽量带原因，如 `"该数据存在关联记录，无法删除！"`。
3. 新增/修改手动填充时间：`setCreateTime(LocalDateTime.now())`、`setUpdateTime(...)`。
4. 多表写操作加 `@Transactional(rollbackFor = Exception.class)`。
5. **循环内不查库**：先批量预取（`selectByIds(ids)` 一次查回），再内存组装。
6. 当前登录人从 `SecurityUtils.getCurrentUserId()` 取（内部读 SecurityContextHolder，返回 String，比较时转型；未登录返回 null）。

## 7. Mapper / MyBatis 写法 ⚡

### 7.1 接口

```java
@Mapper
public interface XxxMapper {
    List<Xxx> selectList();
    Xxx selectById(Long id);
    int insert(Xxx xxx);
    int update(Xxx xxx);
    int delete(Long id);
    // 多参数必须 @Param 命名，单参数可省略
    List<XxxVO> selectByCondition(@Param("kw") String kw, @Param("type") String type);
}
```

### 7.2 XML

- 路径 `resources/mybatis/mapper/XxxMapper.xml`，**文件名与接口一致**，`namespace` = 接口全类名。
- `resultType` 写**全类名**（含内部类用 `$`：`com.xx.vo.XxxVO$InnerVO`），不用 `resultMap`。
- 开启驼峰映射的前提下，查询列仍**显式起别名**：

```xml
<!-- 查询列表，映射XxxVO -->
<select id="selectList" resultType="com.xx.vo.XxxVO">
    SELECT
        a.id AS id,
        a.create_time AS createTime,
        DATE_FORMAT(a.submit_time, '%Y-%m-%d %H:%i:%s') AS submitTime,
        u.name AS userName
    FROM xxx a
    LEFT JOIN user u ON u.id = a.user_id
    <where>
        <if test="kw != null">AND a.name LIKE CONCAT('%', #{kw}, '%')</if>
    </where>
    ORDER BY a.id DESC
    LIMIT #{offset}, #{pageSize}
</select>
```

- 时间出参一律 `DATE_FORMAT(..., '%Y-%m-%d %H:%i:%s')` 转字符串，VO 字段用 `String`。
- 动态 SQL 用 `<where>` + `<if>` / `<set>` / `<foreach>`；存在性判断 `SELECT COUNT(*) > 0`。
- **每个语句上方写中文注释** `<!-- 中文说明 -->`。

#### 7.2.1 SQL 书写硬性规则（13 条）

1. **关键字全大写**：`SELECT/FROM/WHERE/AND/OR/JOIN/ON/GROUP BY/ORDER BY/LIMIT/INSERT INTO/VALUES/UPDATE/SET/DELETE` 从头到尾保持大写，禁止前半句大写、后半句小写（`SELECT ... where ...` 是典型错误）。
2. **运算符两边留空格**：写 `WHERE id = #{id}`，不写 `WHERE id=#{id}`。
3. **禁止 `SELECT *`**（含 `c.*` 等别名星号），一律显式列出每一列。理由：表加列后行为不透明、传输冗余、列表查询极易把 `password` 等敏感列带出。
4. **每个语句一条顶部中文注释，且必须与紧随其后的语句一一对应**——注释写错位置比不写更危险，会直接误导维护者。
5. **格式统一**：`SELECT` 后每列一行、逗号结尾；`FROM`/`JOIN`/`WHERE`/`ORDER BY` 各起一行；不把短语句挤成一行。
6. **分页只允许一种写法**：`LIMIT #{offset}, #{pageSize}`，禁止 `LIMIT #{pageSize} OFFSET #{offset}` 等其他写法混入。
7. **类型写法统一**：对象用全类名；单值类型**统一用包装类型**（`java.lang.Long`、`java.lang.Boolean`），不与 `long`/`boolean` 混用；单参数 `parameterType` 可省略，但同一项目保持一致。
8. **列表与计数必须同条件**：分页的 `list` 与 `count` 两条 SQL 筛选条件必须完全一致（同字段、同别名、同 JOIN），否则 `total` 与列表对不上。用 `<sql>` 片段复用 WHERE 部分：

   ```xml
   <sql id="listWhere">
       <where>
           <if test="kw != null and kw != ''">AND a.name LIKE CONCAT('%', #{kw}, '%')</if>
           <if test="clazzId != null">AND a.clazz_id = #{clazzId}</if>
       </where>
   </sql>
   ```

9. **聚合统计先筛后聚**：要“近 N 次/最近 N 条”，必须先用子查询取出这 N 行再聚合。**禁止**在无 `GROUP BY` 的聚合查询上写 `ORDER BY ... LIMIT N` 来冒充——聚合只返回一行，ORDER/LIMIT 根本不会先筛选，统计的仍是全部数据；在 ONLY_FULL_GROUP_BY 模式（MySQL 8 默认）下还会直接报错。
10. **业务字面量集中管理**：状态/类型值（`'已批改'`、`'未提交'` 等）不得散落在多个 XML 里手写，统一放 Java 常量或 `<sql>` 片段，SQL 与代码引用同一来源，防止文案漂移导致统计口径不一致。
11. **复杂条件显式加括号**：`AND`/`OR` 混用必须括号分组，不依赖隐式优先级；批量插入固定列结构，不用 `foreach + if test="index == 0"` 这种“首个元素决定所有行列结构”的脆弱写法。
12. **敏感列不出列表**：展示类查询不查 `password` 等敏感字段；确需读取走单独 `selectById`，且响应 VO 不透出。
13. **唯一键查重 SQL 与唯一键同口径**：逻辑删除表（带 `deleted` 列）的唯一键查重 `COUNT` **不得**过滤 `deleted = 0`——已删除行仍占用全局唯一键（如 `uk_username`），过滤后预检查放行、INSERT 必撞 `DuplicateKeyException` 变成「系统繁忙」。查重条件 = 唯一键条件（`WHERE username = #{username}`，不带 `deleted`）；登录/详情等"当前有效数据"的存在性查询才过滤 `deleted = 0`。另在全局异常处理器为 `DuplicateKeyException` 兜底返回中文提示。

### 7.3 全局配置（`mybatis-config.xml`）

```xml
<setting name="logImpl" value="STDOUT_LOGGING" />   <!-- SQL 打到控制台，开发期保留 -->
<setting name="mapUnderscoreToCamelCase" value="true" />
```

## 8. entity / dto / vo 约定

| 类型 | 位置 | 命名 | 用途 |
|---|---|---|---|
| 实体 | `entity/` | 表名驼峰：`User`、`Order` | 对应表结构 |
| 入参 | `dto/` | `XxxDTO` | 参数多、需要校验时用 |
| 出参 | `vo/` | `XxxVO` | 聚合/脱敏后的响应结构（**统一大写 VO 后缀**） |

- 三者全部 Lombok `@Data`；ID 用 `Long`，时间用 `LocalDateTime`。
- DTO 校验用 `jakarta.validation`（`@NotNull(message = "xxx不能为空")`），Controller 方法加 `@Valid`。
- DTO/VO 字段使用**行尾中文注释**对齐说明用途。
- 复杂出参用**嵌套静态类**：`XxxVO` 内 `private List<ItemVO> itemList;` + `public static class ItemVO`。
- 实体的非表字段：`private transient List<...> xxxList;`（序列化忽略），或 `Map<String, Object> extendData` + `addExtendData(key, value)` 动态扩展。

## 9. 登录认证与当前登录人（通用设计）⚡

```text
登录成功 → 生成 JWT → 写入 HttpOnly Cookie（name=authToken，path=/，7天）
请求进入 → Spring Security 过滤器链
        → JwtAuthenticationFilter 解析 Token（白名单与 OPTIONS 预检直接放行）
        → 通过后写入 SecurityContextHolder（principal=userId，权限=ROLE_xxx）
请求结束 → 框架 SecurityContextPersistenceFilter 的 finally → SecurityContextHolder 自动清理
```

- 认证走 Spring Security 无状态过滤器链（`SessionCreationPolicy.STATELESS` + 关闭 CSRF），**不自建登录拦截器**。
- 白名单集中在 `SecurityConfig` 配置：登录/注册/健康检查/`/error` + `OPTIONS /**`，其余接口 `anyRequest().authenticated()`。
- 当前登录人统一通过 `SecurityUtils.getCurrentUserId()` / `getCurrentRole()` 读取：它只是 `SecurityContextHolder` 的静态门面，**不持有状态、无需清理**。
- **禁止自建用户 ThreadLocal**：`SecurityContextHolder` 由框架在请求结束时自动清理；自建 ThreadLocal 还需额外过滤器 `finally` 清理，纯属冗余。
- Servlet 过滤器（确需时）用 `FilterRegistrationBean` 注册：`/*`、`order(1)`；**不要再加 `@WebFilter` 注解**（避免双注册）。

## 10. 配置习惯 ⚡

- **一个项目只保留 `application.yml`** 作为配置入口（不用 properties 混放）。
- MyBatis：`type-aliases-package` 指到 entity 包，`mapper-locations: classpath:mybatis/mapper/*.xml`。
- 安全、跨域、数据源各自独立 `@Configuration` 类，职责单一。
- 密钥/第三方 Key 用环境变量注入：`api-key: ${XXX_API_KEY}`，**不提交明文**。
- 自定义配置用专属前缀（如 `jwt.secret`、`jwt.expire`），`@Value` 注入。

## 11. 注释与命名风格

- 注释、Javadoc、错误文案、日志**全部中文**，标点用全角 `，。！`。
- 类头：`/** 业务名 + 角色/职责说明（可多行） */`。
- 方法步骤用编号注释：`// 1. 参数校验`、`// 2. 存在性校验` ……
- 关键行解释「为什么」：`cookie.setHttpOnly(true); // 设置为HttpOnly，防止XSS攻击`。
- 命名：包名全小写；类名大驼峰；方法/字段小驼峰；常量全大写下划线。
- Mapper 查询方法统一 `selectXxx`（列表可用 `listXxx`，但一个项目内保持一致）。

## 12. 新增接口标准模板（Checklist）

以「导出数据」为例：

**① Controller**（四字段 Javadoc + 一行转发）

```java
/**
 * 导出XX数据（管理员）
 * 请求方式：GET
 * 请求路径：/xxx/export/{id}
 * 路径参数：id（记录ID）
 * 返回值：Excel 文件流（.xlsx 附件）
 */
@GetMapping("/export/{id}")
public void export(@PathVariable Long id, HttpServletResponse response) throws IOException {
    xxxService.export(id, response);
}
```

**② Service 接口**：中文 Javadoc + `@param`/`@return`。

**③ Service 实现**：按第 6.2 节步骤顺序写，文件导出失败时用 JSON 写回 `R.error`（设置对应 HTTP 状态码），不抛裸异常。

**④ Mapper**：接口方法（多参数 `@Param`）+ XML 语句（中文注释、显式别名、`resultType` 全类名）。

**⑤ 编译验证**：`mvn -q -DskipTests compile`。

自查清单：

- [ ] Javadoc 五块齐全（描述 + 请求方式/路径/参数/返回值）
- [ ] 错误信息中文 + `！`，提前 return，无未处理异常
- [ ] 循环内无查库（批量预取）
- [ ] 多参数 Mapper 加 `@Param`，XML 文件名与接口一致
- [ ] 分页默认值 1/10，返回 `R.success(list).add("total", ...)`
- [ ] 当前登录人取自 SecurityUtils，未自建用户 ThreadLocal
- [ ] 配置无明文密钥

## 13. 反模式自查（避免项）

| ❌ 反模式 | ✅ 正确做法 |
|---|---|
| Controller 里写业务、注入 Mapper | Controller 只转发，业务全在 Service |
| 用异常做流程控制（`throw` 业务错误） | `return R.error(...)` 提前返回 |
| 循环内逐条查库（N+1） | 批量 `selectByIds` 预取 + Map 组装 |
| 项目里同时存在 properties 和 yml | 只保留 application.yml |
| `@WebFilter` + `FilterRegistrationBean` 双注册 | 只用 `FilterRegistrationBean` |
| 密钥/密码明文提交 | 环境变量注入；密码哈希存储 |
| VO 后缀大小写混用（`XxxVO`/`XxxVo`） | 统一 `XxxVO` |
| 错误文案英文/无标点 | 中文 + 全角 `！`，带原因 |
| 文件下载接口返回 `R<String>` 提示 | 直接写 HttpServletResponse 附件流 |
| SQL 关键字大写一半小写一半（`SELECT ... where ...`） | 关键字从头到尾全大写 |
| `SELECT *` / `c.*` | 显式列出每一列 |
| 分页 `list` 与 `count` 两条 SQL 条件不一致 | `<sql>` 片段复用同一 WHERE |
| 无 GROUP BY 的聚合上加 `ORDER BY/LIMIT` 冒充“近N次” | 子查询先筛 N 行再聚合 |
| 状态字面量散落在多个 XML（`'已批改'`） | 集中常量 / `<sql>` 片段统一维护 |
| 列表查询带出 `password` 等敏感列 | 展示类查询不查敏感列 |
| 唯一键查重 COUNT 过滤了 `deleted = 0`（已删除行占号 → DuplicateKeyException） | 查重 COUNT 与唯一键同口径，不加 `deleted` 条件 |
| 注释写在了别的语句头上（注释错位） | 每条语句的顶部注释与其一一对应 |
